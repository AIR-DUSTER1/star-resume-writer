# star-resume-writer

让 AI 帮你写简历时，不再产出「假大空」和「技术堆砌」。

这是一个**通用**的 AI 技能包（Agent Skill）。任何支持 Agent Skills 规范的助手都能用——装上之后，AI 在改简历时会把 STAR 法则、业务化叙述、真实性核验、版面验收当成硬约束，而不是凭感觉发挥。

---

## 它解决什么问题

AI 写简历常见的四类翻车，这个 skill 逐个堵住：

| 问题 | 表现 | 本 skill 的约束 |
|---|---|---|
| **编造** | 擅自加技术栈、编数字、把没做过的项目写进去 | 每个技能词必须能溯源到依赖清单 / 源码 / 文档原文 |
| **贴标签** | 把 S/T/A/R 当字段贴在简历上 | STAR 内化在叙述里，禁止出现字母标签 |
| **堆技术** | 「用 Vue3/TS/Pinia/Vite/ECharts 实现了…」 | 先讲业务痛点，技术只出现在「为解决问题而用」的位置 |
| **版面崩** | LibreOffice 看是 2 页，Word 打开变 3 页 | 按「距底余量 ≥2 行」验收，不按 fill（会误判） |

## 安装

这是一个纯 Markdown 技能包，核心只有一个 `SKILL.md` 文件。任何支持 **Agent Skills** 规范的 AI 助手都能直接使用，不绑定特定产品。

### 方式一：放对位置（通用）

把整个目录放进你的 AI 助手的 skills 目录，目录名保持 `star-resume-writer`：

| 助手 | 用户级 skills 目录 |
|---|---|
| Claude Code | `~/.claude/skills/` |
| ZCode | `~/.zcode/skills/` |
| 其他遵循 Agent Skills 规范的工具 | 见该工具的文档，通常是 `~/.<工具名>/skills/` |

也可以放在**项目级**目录（如项目根下的 `.claude/skills/`、`.zcode/skills/`），只在当前项目生效。

```bash
# 通用写法：先克隆到任意位置
git clone <本仓库地址> /tmp/star-resume-writer

# 再拷贝到你的 skills 目录（按上表替换路径）
cp -r /tmp/star-resume-writer ~/.claude/skills/
```

Windows（Git Bash）：

```bash
cp -r /tmp/star-resume-writer /c/Users/<你的用户名>/.claude/skills/
```

### 方式二：直接下载

下载本仓库 ZIP，解压后把整个 `star-resume-writer` 目录放进上表对应的 skills 目录即可。

### 方式三：手动接入其他工具

如果你的 AI 助手不支持 skills 目录，直接把 `SKILL.md` 的内容贴进它的系统提示或自定义指令里，效果等价。

装完后新开一个会话生效。

---

## 它不依赖特定平台

- **纯文本**：全站 Markdown，无脚本、无二进制
- **无外部依赖**：只有 §9 的验收脚本需要 Python + `pymupdf`，写作规范部分零依赖
- **路径无关**：不写死任何人的目录结构，首次使用会先探测你的项目形态

## 用法

装好后直接说需求即可，skill 会自动触发：

- 「帮我改简历」
- 「这段工作经历怎么写」
- 「加个技能，突出 AI 能力」
- 「简历压到两页」
- 「看看简历有没有编造的内容」

## 包含什么

10 章规范，约 480 行：

| 章节 | 内容 |
|---|---|
| §1 初始化 | 不绑定路径，先探测项目形态（有脚本 / 只有 DOCX / 模板引擎） |
| §2 铁律 | 十条硬约束：不编造、STAR 内化、业务化优先、删改先 dry-run |
| §3 工作流 | 改源数据 → 构建 → 版面验收 → 读图 → 关键词核验 |
| §4 版面验收 | 按「距底余量」判断，附实测误判案例 |
| §5 写作规范 | STAR 内化范式、严禁贴标签、严禁三行压缩、业务化翻译公式 |
| §6 ATS 策略 | 全称规则（H5→HTML、K8s→Kubernetes）、禁斜杠压缩、JD 词频统计 |
| §7 真实性核验 | 技能词溯源、四级能力选级标准、文档引用要指到行号 |
| §8 失效工具 | 记录已知失效的路径与替代方案 |
| §9 交付清单 | 一段可直接运行的验收脚本 |
| §10 常见坑 | 11 条实战踩坑速查 |

## 验收脚本

§9 里的脚本可直接跑，自动检查四件事：

```bash
python -I - <<'PY'
# 见 SKILL.md §9 完整版
PY
```

检查项：

- 是否出现硬标签（`S 情境` / `T 目标` / `A 行动` / `R 结果`）
- 是否用了三行压缩结构（`做了什么：` / `用什么方法：` / `结果数字：`）
- 是否出现弱动词（`负责` / `参与` / `协助` / `交付`）
- 每页距底余量是否 ≥25pt（防 Word 崩页）

输出示例：

```
[OK  ] 张三-后端工程师-简历.pdf  2页 距底余量=[26.0, 68.2]pt
[FAIL] 李四-前端工程师-简历.pdf  2页 距底余量=[11.5, 120.0]pt
        ! 余量不足 25pt 的页: [11.5]（Word 可能多出 1 页）
```

## 核心写作范式

不是让 AI 写「S 情境：…T 目标：…」，而是让四要素融进一段连贯叙述：

> 会员积分结算系统（从 0 到 1 独立建设）：积分规则分散在运营、财务、客服三套表格里，对账每次都要人工核对、月底常出错。独立承担结算模块从 0 到 1 建设，落地积分发放 / 核销 / 过期回收全流程与流水追溯；结果：三方在同一系统内核对账目，每笔变动可追溯到操作人 / 规则版本 / 时间，人工对账从两天缩短到半天。

四要素齐（背景 / 目标 / 动作 / 结果），零标签，读起来是一段话。

---

## 不包含什么

- 不含任何个人信息（姓名、联系方式、公司名、项目名）——示例全部中性化
- 不绑定特定人的职业背景或行业
- 不依赖特定仓库路径或构建脚本

任何领域、任何岗位的简历都能用。
